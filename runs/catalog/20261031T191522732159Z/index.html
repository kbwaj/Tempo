Real model output

The reviewable source patch

Deduplicate category and FX keys within each (tenant, snapshot), then partition each kind into batches of at most batch_size. Each batch uses one shared api() task, shielded from cancellation by individual jobs. This minimizes logical enrichment requests to the sum of ceil(unique keys / batch_size) across scopes and kinds. Each product retains its own inventory read, exact transform, receipt order, and stable write key. Transport initialization, admit(), and api() are preserved.

Comparators, scope and audit trail

The configured baseline already uses burst-aware quota admission, concurrency limits, stable write keys, bounded retries and timeouts. Only business dataflow is changed. A manually authored semantic reference produced 108 requests · 1.837s. Matching that implementation shows that the AI applied ordinary batching and sharing correctly; no novel algorithm or superiority over expert redesign is claimed.

Lookups are explicitly immutable within (tenant, snapshot). A batch costs one request. The inventory proof remains item-specific. These are synthetic provider assumptions, not claims about a named production API.

The validation matrix includes tenant/snapshot collisions, batch size one, and a low-sharing boundary. Correctness is required there; a speedup is not promised for every workload. All proposal attempts and earlier experiments remain available in the engineering lab.
